Issue to Production

A real process built on what Part 10 shows. Claude does the work in a sandbox and opens the pull request. People decide what gets built, approve the code and approve the release. A pipeline, not Claude, deploys to production.

People hold the decisions

  • Which issues Claude works on (the label)
  • Whether the code is good (review)
  • When it reaches users (UAT sign-off, release approval)

Claude holds one key

  • A token for the Dev sandbox only, in its cloud environment
  • Pushes only to claude/ branches; can’t merge
  • Can be sent back by a comment and the label

GitHub enforces the rules

  • Branch protection: a review and passing checks before merge
  • Actions hold the QA, UAT and production credentials
  • Production runs in a protected environment with required reviewers

Each org has one job

  • Dev: where Claude builds and runs its tests
  • QA: a check-only deploy with every local test
  • UAT: what people try before release
  • Production: only the pipeline deploys here

The steps

  1. File an issue. Anyone can describe a bug or a small feature.
  2. Triage. Someone with write access decides it’s worth doing and adds Claude Review.
  3. Claude builds it on claude/issue-<n>, deploys to the Dev sandbox with its tests, and keeps the issue updated.
  4. Pull request. Claude opens it with “Fixes #n” and the deploy and test results.
  5. CI checks it (GitHub Actions): sf project deploy validate against QA with RunLocalTests, plus Code Analyzer. Nothing changes in QA.
  6. Code review. A person approves, or comments what to change and re-adds the label, and Claude picks up the same branch.
  7. Merge to main, allowed only after the review and green checks.
  8. CD deploys to UAT so people can try it with realistic data.
  9. Sign-off. UAT passes and a release approver approves the production job.
  10. Deploy to production. The pipeline validates against production first (a check-only deploy with every local test), then releases exactly that validated package with sf project deploy quick, so nothing new slips in between the check and the release.
