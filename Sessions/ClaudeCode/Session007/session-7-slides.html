Empty Terminal to Finished Video

Two tools, four builds. Almost all of it live in the terminal.
  • Set up the toolchain — install Playwright CLI and HyperFrames, and their skills, from nothing
  • Learn the tool on something trivial — a circle that moves, then captions, then a voiceover
  • Capture a real Salesforce screen — and highlight what the narration is talking about
  • Do the whole walkthrough — multi-step capture, multiple scenes, one narrated video
Why it matters
Documentation rots because the second pass costs as much as the first. When the capture and the composition are files on disk, the re-shoot next release is nearly free.

Tool 1

Playwright CLI

A command-line interface for browser automation designed for coding agents. Token-efficient commands and installable skills let agents balance browser automation with large codebases and reasoning within limited context windows.
Key Features
  • Token-efficient — concise CLI output avoids loading large tool schemas into the model context
  • Skill-based — agents discover capabilities through installable skills rather than verbose help text
  • Daemon architecture — persistent browser process means no startup cost per command
  • Ref-based — accessibility snapshots with element refs for deterministic interaction
  • Cross-browser — Chrome, Firefox, WebKit, and Edge support
  • Sessions — multiple isolated browser instances with separate state

Tool 2

What is HyperFrames?

HyperFrames is an open-source framework that turns HTML into video. You make the request; an AI agent builds an editable project; HyperFrames plays or renders it.
Three Things to Know
  • Agent-built. You describe the video; the agent writes the HTML, CSS, and JavaScript. You do not need to write code for this path.
  • Editable. The result is a project folder, not a flattened black box. An agent, Studio, and your own tools can work on the same files.
  • Reliable render. HyperFrames asks the project for each exact frame instead of depending on live playback, so a slow machine does not drop moments from the finished video.
HyperFrames is free and open-source, and local rendering does not use HeyGen credits. Your coding agent and any optional hosted, voice, avatar, or generated-media services may have their own costs.

Tool 2  ·  The Project

How a HyperFrames Project Works

A HyperFrames project is a folder your agent can create and you can keep editing. Its HTML is the video: it describes the scenes, timing, motion, media, and reusable parts that HyperFrames plays or renders.
project/
├── BRIEF.md         what the video must communicate
├── STORYBOARD.md    the planned sequence and review state
├── SCRIPT.md        locked narration, when the video has it
├── frame.md         visual direction, when needed
├── index.html       the main composition
├── hyperframes.json project settings
├── compositions/    scenes and reusable visual parts
├── assets/          images, video, audio, and fonts
└── renders/         finished files

One folder of HTML is the whole video. Every tool reads and writes those same files — there is no export step between them and no second version of the project.

Only the project source is essential. Planning files exist to preserve decisions across reviews and agent sessions.

Tool 2  ·  Compositions

Time Is Part of the Source

A composition is a finite, seekable piece of the project. The main composition is the complete sequence. Timed elements carry their start, duration, and track in HTML:
<img
  id="product-shot"
  class="clip"
  data-start="2"
  data-duration="3"
  data-track-index="1"
  src="./assets/product.png"
/>
This image starts at two seconds, remains for three seconds, and appears on track one. Animation timelines are paused and seekable, so Studio, the Player, and the renderer can request an exact moment without playing from the beginning.
Why rendering can repeat the same moment
HyperFrames seeks the composition to an exact time, captures the frame, and advances. For the same source, media, and settings, an exact timestamp should resolve to the same project state. Compositions therefore avoid the current clock, unseeded randomness, and render-time network requests.

Tool 2  ·  Getting Started

Make Your First Video

1. Install the skills
npx skills add heygen-com/hyperframes --full-depth
Choose Core Skills in the picker. Keep --full-depth so the installer uses the current repository version. Then open or restart your coding agent in that folder.
2. Ask for the video
Using /hyperframes, make a 10-second
product intro for https://example.com
The agent will propose a direction and ask for anything important that is missing. You do not need to write a production specification.
3. Continue
npx hyperframes preview
The agent leaves you with an editable project folder and opens its local preview. Watch the first version once; it is not a guaranteed final cut.

How I Use These Tools

One Capture Pass, Two Artifacts

Where You Take It Next

Possible Enhancements

None of this is needed for your first video. Each one makes the tenth video faster and more consistent than the first.
  • Better voice, and music beds. Swap the local Kokoro voice for ElevenLabs when the video is customer-facing, and lay a music bed underneath. Costs money, sounds it
  • A brand folder. Colors, fonts, logo, and the rules for using them, sitting in the project where the agent reads them — so you stop re-specifying your palette in every prompt
  • Your own skill. Wrap your preferences — house style, default length, caption treatment, where renders go — into a skill, so the tenth video starts where the ninth ended
  • A reusable capture script. The saved browser state plus the shot list is the asset. Next release, re-run it and only the changed screens need attention
  • Publish and template it. Share a project by URL, and use variables to produce the same video for a different product, customer, or org
