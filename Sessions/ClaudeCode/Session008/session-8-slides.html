Unit Tier  ·  Jest

Jest for Lightning Web Components

Jest is a JavaScript testing framework. Salesforce's sfdx-lwc-jest runs it against the LWCs in a Salesforce DX project.
What It Tests
  • A component in isolation
  • Its public API: properties, methods, events
  • Basic user interaction, like clicks
  • The DOM it renders
  • That events fire when expected
Runs locally, no browser, no org. Tests live in __tests__, go to version control, and never deploy to Salesforce. Apex calls and base components are mocked.
# A generated SFDX project already includes sfdx-lwc-jest
npm install

# Older project? Add it manually
npm install @salesforce/sfdx-lwc-jest --save-dev

# Run (add :watch for instant feedback)
npm run test:unit

# Use the Node.js LTS release, per Salesforce docs
Salesforce recommends
"We recommend using Jest to unit test individual Lightning web components. Use UI testing tools like Selenium WebDriver only for end-to-end testing."
REFERENCES developer.salesforce.com/docs/platform/lwc/guide/testing.html github.com/salesforce/sfdx-lwc-jest github.com/trailheadapps/lwc-recipes

Unit Tier  ·  Apex

Apex Tests

Test classes marked @isTest run in the org and check server-side logic: classes and triggers.
How It Works
  • Test methods call your classes directly
  • Tests create their own records; existing org data is hidden by default
  • Nothing is saved: test data is never committed
  • Each run reports pass/fail and code coverage
# Run one test class, with coverage
sf apex run test -o cws \
  --class-names CalcHistoryControllerTest \
  --code-coverage \
  --result-format human
Salesforce requires
"To deploy Apex or package it for the Salesforce AppExchange, unit tests must cover at least 75% of your Apex code, and those tests must pass."
REFERENCES Apex Developer Guide: Testing and Code Coverage Apex Developer Guide: Understanding Test Data

End-to-End Tier

End-to-End Tests

One user action, run against the real org, checked everywhere the result should land.
What Makes It End to End
  • Runs in a deployed org, with nothing mocked
  • Follows one user action all the way through
  • Tests the component, the backend logic, and third-party systems together
  • Unit tests check each piece on its own. They can't show the pieces work together
One scenario: 60 + 7

End-to-End Tier  ·  UI

The Playwright CLI

A browser Claude drives from the command line, one step at a time, against the running org.
How Claude Uses It
  • snapshot reads the page and gives each element a ref, like e15
  • click and fill act on those refs
  • Every step is a shell command, so every step shows in the transcript
  • Login comes from the Salesforce CLI, so no password is stored
# Install once
npm install -g @playwright/cli

# Get a login URL for the org
sf org open -o cws --url-only

# Open it, read the page, act on it
playwright-cli open "<login URL>"
playwright-cli snapshot
playwright-cli click e15
playwright-cli close
REFERENCES github.com/microsoft/playwright-cli
